# config

- `models.toml` — provider endpoints, pinned model names, the outbound host allow-list split into `eu_hosts` and `external_hosts` (P0-03, P1a-09), and the model `[[catalogue]]` (P1a-09): per model its provider, display name, reasoning switch kind, price per million tokens in and out in cents of its `currency` (`EUR` or `USD`; the usage ledger converts USD at `[pricing] usd_to_eur`, which startup requires when a USD entry exists), optionally `price_placeholder = true` while prices are placeholders (the API logs a warning per such entry at startup; none is now), whether it is served outside the EU, and for OpenRouter entries an optional provider pin (`provider_order`, `provider_only`) sent with zero-data-retention routing always applied on top.
- `prompts/<name>/<version>.md` — versioned prompt templates (P0-12). The active version of each is set in `models.toml` `[prompts]`; a released version file is never edited, a change is a new version plus an eval run.
  - `corpus_only/` — system prompt for corpus-only answers. From `v2` (P1a-06) it carries the workspace's additional-instructions slot, below. `v3` (findings section 11) adds the decide-then-answer abstention with a fixed reply, citation rules that no instruction can change, an explicit secrecy rule and the order of authority. `v4` (findings G8) answers comparison and cross-source questions from the passages taken together and gives a partial answer before declining, keeping v3's near-miss test for specific facts. `v5` (findings G9) adds to rule 4 that a combined answer gives each passage's statement with its own citation and marks a conclusion drawn across them as one.
  - `general_knowledge/` — system prompt for the general-knowledge answer mode (P1a-06), with the same slot. `v2` (findings section 11) adds the same citation, secrecy and authority rules.
  - `rewrite/` — system prompt for turning a follow-up into a standalone search query.
  - `judge/` — faithfulness judge of the eval harness (`packages/eval`, P0-18); not used by the API.
- `mail/<name>/<version>.txt` and `.html` — versioned platform email templates (P1b-11), SporeBot-branded. The active version of each is set in `models.toml` `[mail.templates]`; like prompts, a released version is never edited. The text file starts with a `Subject: ` line and a blank line, then the plain-text body; the HTML file is the HTML body. A template may use `$product` (SporeBot), `$app_url` (`[mail] app_url`) and `$recipient_email`, and nothing else: startup refuses any other placeholder, so an email can carry no identifier beyond the recipient's own address (no tenant, user, notice or job ID, no tenant or display name). Operator notices therefore name no tenant; the console's notices do.
  - `invitation/` — to an invited user (the operator's first-admin invite and a tenant admin's invite): where to sign in, with which address.
  - `spend_cap_80/`, `spend_cap_100/` — to every operator when a tenant's external spend reaches 80 or 100 percent of its cap.
  - `tenant_name_flag/` — to every operator when saved workspace instructions name the tenant or its people (P1a-07).
  - `consent_notice/` — to a user when the use and privacy notice changes; template only, sent by the consent gate (P1b-10).

## Platform mail (P1b-11)

`[mail]` in `models.toml` picks exactly one provider: `scaleway` (Scaleway Transactional Email's HTTP API, fr-par, `[mail.scaleway]` with the pinned `api_version`) or `mailgun` (the backup, Mailgun's EU region, `[mail.mailgun]`, only after its DPA is filed). Both hosts are on `allow_list.eu_hosts`; startup refuses a mail host that is not, and plain HTTP. Keys come from the environment: `SCALEWAY_TEM_API_KEY`, an IAM key whose policy allows Transactional Email on the sending project only (the Generative APIs key's policy does not cover it, and a narrower key limits what a leak exposes), with `SCALEWAY_TEM_PROJECT_ID` (or `SCALEWAY_PROJECT_ID`); or `MAILGUN_API_KEY`. Without the active provider's key the API still starts and nothing is sent: each `send_mail` job fails with `mail_not_configured`.

## The workspace-instructions slot (P1a-06)

A mode prompt may contain one section between `{{#workspace_instructions}}` and `{{/workspace_instructions}}`, holding one `{{workspace_instructions}}` placeholder. `app.chat.prompts.render_system` replaces the placeholder with the workspace's active additional instructions (tenant-authored, capped at 2,000 characters, HTML-escaped so the text cannot close its `<workspace_instructions>` element), or drops the whole section when there are none. The text around the placeholder, which tells the model that the block is tenant-authored and lower priority than the platform rules, lives in the prompt file like every other instruction. Startup refuses a prompt whose slot markers are malformed.

#### Findings, one per rule

1. **Dataset IDs never from the client — proven, note.** All 34 request bodies in `apps/api/openapi.json` were enumerated: none has a dataset, document or chunk field; every JSON body has `additionalProperties: false` (`_In`, `app/api/schemas.py:41`), including the four SSO source bodies and `ConsentAcceptIn`. The two multipart bodies (`POST /content/sources`, `PUT …/licence`) carry file, metadata and tag keys only. `ApproveIn.replaces` is our register UUID and is refused unless it is in `replacement_candidates` (`app/content/register.py:306`). The content console builds RAGFlow UI links server-side from the register (`app/api/content.py:199`) and `sync` takes no ID (`content.py:943`). Retrieval still goes through `resolve_package` (`app/chat/package.py:61`) and `select_context` drops out-of-package chunks (`orchestrator.py:441,464`). Fix: none.

2. **No tenant, user or package identifiers to an LLM — proven.** `answer_messages` (`app/llm/mistral.py:158`) sends system prompt, history turns (`Turn(role, content)`, built from `messages.content` only, `orchestrator.py:335`), `<context>` passages (`PromptChunk`: publisher, title, date, page, text, `trust="untrusted"`; `for_prompt()` at `app/chat/context.py:38` strips IDs) and `<question>`. `rewrite_messages` (`mistral.py:170`): rewrite system prompt, turns, question. `judge_messages` (`mistral.py:177`): judge prompt, passages, numbered statements; the eval harness's `build_request` (`packages/eval/eval/judge.py:89`) builds its `PromptChunk`s from citation publisher and title and chunk text, never chunk or source IDs. The failover path (`app/llm/factory.py:227`) reuses the same four arguments; the OpenRouter body is `provider` (pin then ZDR) plus reasoning, no `user` field, no attribution headers (`app/llm/openrouter.py:104`). Fix: none.

3. **No request or response bodies in logs — proven, backlog note.** All 79 `log()` calls added since 6516048 were dumped by AST and read. New allow-list fields (`app/core/logging.py:29-66`): `reasoning_tokens` (int), `job_id`, `job_type`, `attempts`, `site_id`, `template` (DB-constrained `^[a-z0-9_]{1,64}$`, sliced to 64), `consent_version` (schema `^v[1-9][0-9]*$`), `table` (name from the fixed purge list), `certificate` (generated `COD-…` number). None can carry a body. Every `error_code` value traces to a class constant or `mail_<status>` (`app/core/mail.py:136`); no `error_code=str(exc)` anywhere. `app/mail/*` and `app/core/mail.py` contain no `log()`; the worker's `mail.job` line (`app/content/worker.py:191`) carries job ID, template, status, code. Exception paths log `type(exc).__name__` only (`worker.py:319`, `orchestrator.py:328`, `v1.py:387`, `main.py:67`). The provider response body is never read. `test_logging_policy` still scans all of `app/`. Fix: none. Backlog: `FetchError` messages include the URL (`fetch.py:187-204`); only `.code` is logged today, keep it that way (add to the static policy test if cheap).

4. **tenant_id + RLS + tenant-first index on every tenant table — proven; `jobs` ruled acceptable with a backlog line.** New tables: `content_roles` (0013: forced RLS, `tenant_isolation`, tenant-first PK), `tenant_login_policy` (0020: forced RLS, PK `tenant_id`, operator and auth policies), `sso_attempts` (0021: forced RLS, `ix_sso_attempts_tenant_id_created_at`), `mfa_challenges` (0022: forced RLS, `ix_…_tenant_id_user_id_created_at`). `jobs` (0014), `sites` and `site_pages` (0024) have no `tenant_id` column by design (operator-owned shared tables, like `sources`). `test_schema.py::test_tenant_tables_list_is_complete` derives the list from `information_schema`, so the four new tables are in `LATER_TENANT_TABLES` and get the per-table forced-RLS, policy, index, zero-rows and cross-tenant-write tests. Column additions (0015, 0023, 0024, 0032, 0040, 0041) are on tables already under RLS; 0015, 0040 add NOLOGIN roles with column-level grants only.
   **`jobs` ruling: acceptable with a backlog line (not a blocker, not before-first-client).** Readers: `askspore_app` (SELECT/INSERT/UPDATE, 0014) and `askspore_operator` (SELECT/INSERT, 0030). Routes: only the content console's source and site detail (`app/api/content.py:365`, internal-tenant content roles, 403 for everyone else), and `JobOut` (`content_schemas.py:73`) exposes id, type, status, error_code, attempts, dates — never the payload. No `/api/v1`, `/admin` or files route, and no export, touches `jobs`. Payload keys are DB-constrained to `source_id, site_id, add_tags, downloadable, parse_timeout, template, tenant_id, user_id, notice_id` with a 2 KB cap (`0030:40`), so an address, subject or body cannot be stored (`test_mail.py:624`, `test_jobs.py:317`). The termination purge deletes a tenant's jobs by payload (`termination.py:282`). Residual: an unscoped app-role session can read which user of which tenant was invited (identifiers only). Concrete fix for the backlog: enable and force RLS on `jobs` with a policy for `askspore_app` `USING (payload->>'tenant_id' IS NULL OR NULLIF(current_setting('app.tenant_id', true), '') IS NULL OR payload->>'tenant_id' = current_setting('app.tenant_id', true))` (tenant-scoped sessions see their own tenant's jobs; the worker's and CLI's unscoped sessions and `askspore_operator` see all), plus a test that a tenant-scoped session reads zero rows of another tenant's mail jobs. Do it before any tenant-facing route reads `jobs`.

5. **Cache keys tenant-prefixed; no Redis elsewhere — proven.** The only `redis` import under `apps/api/app` and `packages` is `app/core/cache.py`; the new `scan`, `delete` and `clear_tenant` helpers keep the `t:<uuid>:` prefix; TTL capped at 30 days (`cache.py:18`). Fix: none.

6. **Allow-listed endpoints, no hard-coded provider URLs or `-latest`, OpenRouter only with entitlement and ZDR — proven, note.** `config/models.toml` keeps `eu_hosts` (Mistral, Scaleway, ragflow, authentik-server, `api.scaleway.com`, `api.eu.mailgun.net`) apart from `external_hosts` (`eu.openrouter.ai`); startup refuses a host in both lists, a non-EU mail host and alias model names (`config.py:548-624`); the judge (`qwen3.8-27b`, decision 22) is pinned under `[eval]`. Failover (`factory.py:265-267`) reaches OpenRouter only when `authorize` set `failover.external`, through `OpenRouterClient` so ZDR applies; `test_failover.py::test_a_tenant_not_entitled_never_reaches_openrouter_on_failover` asserts `openrouter.requests == []` across unentitled, no-cap and cap-reached cases. Note (no action): `app/auth/authentik.py:531-535` hard-codes Microsoft's `login.microsoftonline.com` and `graph.microsoft.com` as the Entra source's endpoints handed to Authentik; these are identity-provider addresses called by Authentik, not model endpoints called by the API, so the rule is not breached.

7. **Retrieval read-only and tool-free; crawled text untrusted; pinned fetch — proven.** No `tools`, `tool_choice` or `plugins` in any LLM body (`test_mistral:119`, `test_scaleway:106`, `test_openrouter:93`); `trust="untrusted"` still rendered. `PinnedTransport` (`app/content/fetch.py:136`) checks scheme and default port, resolves once, requires every address global and non-metadata (IPv4-mapped and NAT64 unwrapped; `169.254.169.254`, `169.254.42.42`, `fd00:ec2::254`, `100.100.100.200` named), connects to the first address, keeps Host and SNI, pools per hostname, `trust_env=False`, 5 redirects each re-checked. Verified in the worktree's httpx 0.28.1 that an IPv6 pin renders as `https://[addr]/…` and that 6to4, Teredo, ULA, link-local, CGNAT and `::ffff:10.x` are non-global. Tests: `test_crawler.py:422-565` (private, loopback, metadata, IPv6, rebinding on second lookup and on a later request, redirect to internal address, IP literal or other port, redirect cap, proxy ignored). Fix: none.

8. **RAGFlow internal — proven, backlog note.** `infra/caddy/Caddyfile` proxies `/api/*`, `/healthz` and exactly the two SSO callback path regexes to `api:8000`; nothing else. Published ports: Caddy 80/443 (tcp and udp) only; Postgres 5432, Redis 6379, API 8000, web 5173, RAGFlow UI 8080 and Authentik 9000 are all `127.0.0.1:`; RAGFlow 9380 unpublished; no drill Compose files exist under `infra/`. `[ragflow] admin_ui_url` is checked to be a loopback origin. Backlog (carried from 1a §12): a test that parses the Compose files and fails on any non-loopback port other than Caddy's (`test_jobs.py:393` covers only the worker).

9. **Chat history ≤ 30 days — proven.** `RetentionIn` is `ge=0, le=30` (`schemas.py:613`), DB constraint `retention_days BETWEEN 0 AND 30` (0040:57). Retention 0 creates the conversation already expired, takes one question in the 10-minute window and deletes it when the stream closes, with no answer caching (`orchestrator.py:299,539`). `askspore_retention` may SELECT only ID and date columns (`0040:16-21`) and deletes nothing without a tenant scope: `test_retention_purge.py:237`. `[retention] downloads_days` (download records, not chat) accepts up to 3650; owner value 90. Backlog: cap it nearer the owner's figure.

10. **No secrets, `.env`, real documents or real queries — proven.** 146 files added; only `.env.example` files are tracked; no key, PEM or token pattern in the tree at bd1bc46; the added non-code files are mail and consent templates, the compliance drafts, the Authentik blueprint (no secret, tested) and `results/BASELINE(.md)`; no new eval run was committed and `eval gate` confirms the committed results carry no answer or excerpt text.

The moved-image-pins decision is sound: the running images are the reviewed digests, a moved tag is an upstream re-push, not a drift of what runs, and the backlog line (re-pin in its own PR after reading the changelogs) is in place.

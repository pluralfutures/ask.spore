#### Findings, one per rule

1. **Dataset IDs never from the client — proven.** `apps/api/openapi.json`: 72 paths (66 before), 34 request bodies (33 before). The one new body is `WithdrawIn` (`reason` only, `additionalProperties: false`) on `POST /content/sites/{site_id}/withdraw`. The five other new routes (`POST …/sources/{id}/restore`, `POST /admin/users/{id}/invitation`, `POST /operator/tenants/{t}/users/{u}/invitation`, `DELETE /operator/tenants/{t}/users/{u}`, `GET /operator/terminated-tenants`) take path UUIDs of our own rows and no body. Every `*In` schema still has `additionalProperties: false`; the only `dataset_id`/`document_id`/`chunk_id` properties are in `*Out` schemas (responses). New response schemas (`InvitationResentOut`, `SiteWithdrawnOut`, `TerminatedTenantOut`, `MessageOut.truncated/partial`, `MeOut.operator`, `ProposeOut.replaces`) carry our identifiers only. Fix: none.

2. **No tenant, user or package identifiers to an LLM — proven.** `config/prompts/corpus_only/v6.md` differs from v5 in lines 14–16 only (rules 2–4): four clauses added, no sentence removed, no identifier; the `trust="untrusted"` rule, the authority order and the delimited `workspace_instructions` block are byte-identical. `config/models.toml` keeps `corpus_only = "v5"`. `Orchestrator._keep_partial` (`orchestrator.py:341`) persists `"".join(run.shown)` and the citations already shown, then writes one audit event and a `chat.answer` line; it makes no model call. `_keeping` wraps the stream (`:318`) and `_run` sets `run.streaming` only after the provider stream opened (`:583`), so a failure before that stores nothing. Fix: none.

3. **No request or response bodies in logs — proven, backlog note.** `apps/api/app/core/logging.py` is unchanged (allow-list and `ForbiddenLogField` on any other field, `:115`). Every `log()` added since 1a714fe read: `tenant_admin.invitation_resent`, `tenant_admin.remove_refused`, `tenant_admin.user_removed` (`admin.py`: tenant_id, user_id, error_code, count), `user_removal.provider_failed` (error_code from `ProviderError`), the operator twins (`operator.py`), `content.site_withdrawn` (user_id, site_id, count), `sources.restore`/`sources.withdraw` (`cli.py:467,483`: IDs and status), `datasets.counts` (tag, count, chunk_count), `chat.partial_not_stored` (conversation_id, exception class name), `chat.answer` with `status="partial"` and an `error_code` from a class constant or `"stopped"`. SSO: `auth.login`/`auth.login_failed` carry `method = sso:<kind>` and the refusal code; `authentik.source_refusal` (`authentik.py`) extracts only one of three allow-listed codes from Authentik's denied page, else `refused_by_source`; the redirect carries a coarse `reason` (`sso.refusal_reason`), never the code.

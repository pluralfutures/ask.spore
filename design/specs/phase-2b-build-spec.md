### Group A — Answer and notice rendering

**P2B-01 Markdown tables and other GFM in answers and the consent notice.** Models answer
with GitHub-flavoured Markdown tables (seen with Qwen, Oct 27, 2026: a three-column table
shown as one paragraph of `|` text). `react-markdown` without `remark-gfm` treats a table as a
plain paragraph and joins its lines with spaces. The same defect affects the consent notice's
section 8 table (`config/consent/v1.md`, "What we hold").

- Add `remark-gfm` as a web dependency, exact version pinned in `apps/web/package.json`, and
  record it in `design/Stack Decision.md` (web app row) with its licence and why.
- Pass it as a `remarkPlugins` entry in both render sites:
  `apps/web/src/components/AnswerMarkdown.tsx` and `apps/web/src/components/ConsentGate.tsx`.
  Raw HTML stays off (react-markdown's default); the plugin adds no HTML pass-through.
- Table styling with the existing design tokens: header row in the emphasis weight, cell
  borders and padding, left-aligned text unless the column's alignment row says otherwise. A
  wide table scrolls sideways inside its own container (`overflow-x: auto`, with a focusable,
  labelled region for keyboard users) so the page never scrolls horizontally at phone width.
- Citation markers inside table cells keep working: `[n]` in a cell renders as the citation
  button and opens the panel (`linkMarkers` runs before parsing, so this should hold; the test
  proves it).
- The other GFM features the plugin turns on (strikethrough, task-list checkboxes,
  autolinked bare URLs, footnotes) render with plain styling. Task-list checkboxes are
  read-only. Autolinked URLs go through the existing `a` component, so they open in a new tab
  with `rel="noopener noreferrer"` like any other answer link.
- Tests: a unit test that a GFM table in an answer renders as a `<table>` with header cells
  and a working citation button in a cell; one that a table in the consent notice renders as a
  `<table>`; one that raw HTML in an answer is still shown as text. Accessibility: the axe
  baseline passes on a chat page with a table. Visual: regenerate the baselines that show a
  table (consent page) in the pinned Playwright image, and add one for an answer with a wide
  table at phone width.
- No change to prompts, `config/models.toml` or anything the model sees. On completion,
  strike the UX-12 table item in `backlog.md` and point it here.

### Group B — Public static pages

**P2B-02 Legal pages in the app's visual design.** The owner reported on Oct 27, 2026 that
`/legal`, `/legal/privacy`, `/legal/ai` and `/legal/terms` do not follow the visual design of
the rest of the site. Cause: the four pages (P2A-L2, `apps/web/public/legal/`, generated by
`apps/web/scripts/render-legal.mjs`) link `apps/web/public/public-page.css`, the P2A-11
stylesheet written before the UX refresh. It has its own palette (`#0b5cad` links, `#1f2328`
text), the system font stack instead of Lato, no product name or header, and a dark
scheme under `prefers-color-scheme: dark` that the app does not have. The app's design is
the tokens in `apps/web/src/index.css` (UX refresh, `ux-refresh-spec.md`), Lato from
`apps/web/src/assets/fonts/lato/` and the `ProductName` treatment (Poppins 700 "Mycelium",
then "SporeBot").

- Rewrite `public-page.css` from the app's tokens: the same colour values (canvas, surface,
  fg, fg-secondary, muted, link, line), type scale (reading 16/26, title, display, heading)
  and radii, with the values copied as CSS custom properties and a comment naming
  `index.css` as the source. A unit test compares the shared values in the two files so they
  cannot drift. The dark block goes, since the app is light only.
- Fonts: the static pages cannot reference the Vite-hashed font files, so serve Lato (400 and
  700, Latin and Latin Extended) and Poppins 700 from stable paths under `public/fonts/`
  (copies of the vendored files, same licence note, `font-src 'self'` unchanged), or have the
  build emit them at stable names. Pick one at build time and record it in `Stack Decision.md`
  (web app row, typeface).
- Page frame matching the app: a header with the product name as `ProductName` renders it
  (static markup, a link to `/`), the content on a surface card on the canvas background at
  the app's reading width, headings, lists and links styled as in answers, and a footer
  matching `AppFooter` (the "Legal" link to `/legal`). The privacy notice's tables get the
  app's table look (header row in the emphasis weight, `line` borders), the same look P2B-01
  gives tables in answers, and scroll sideways on their own at phone width.
- Keep the P2A-L2 and P2A-11 constraints: plain static HTML, no script, no inline style (the
  CSP is `'self'` only), no API call or sign-in, nothing new logged (P2A-L3). The texts do not
  change; only `render-legal.mjs`'s page template and the index page's markup do, and
  `--check` and `--final` keep working. The generated pages are regenerated in the same commit.
- The same stylesheet serves `/security-disclosure` (P2A-11) and will serve the trust page,
  so they take the new look too. The owner confirms that this is wanted (open item below).
- Tests: `e2e/legal.spec.ts` keeps passing; the axe baseline passes on all four legal pages
  and `/security-disclosure`; new visual baselines for `/legal` and `/legal/privacy` at
  desktop and phone width, generated in the pinned Playwright image; a check that each page
  loads only same-origin resources and no script.
